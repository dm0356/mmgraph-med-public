# 项目定位与方法学框架章程（Project Charter）

> 本文件是项目的"根本定位"，优先级高于任何单次实验结果。
> 后续所有代码、实验、文档都应服从这里的原则。

## 1. 项目是什么

本项目是 **MMGraph-Med**：一个面向"心力衰竭/心肌病患者恶性室性心律失常多模态前驱信号识别 + RAG-LLM 临床预警智能体"的**方法学框架**。

当前阶段的目标不是产出临床结论，而是：

1. 把多模态知识组织、检索、记忆、策略学习、评测的**方法链路**搭好；
2. 用**公开数据 / 合成数据 / 少量脱敏 pilot** 验证每个模块可运行、可替换、可复现；
3. 为合作医院数据（伦理审批通过后）的正式接入做好**接口、schema、评测协议、合规边界**的准备。

## 2. 当前不是什么

- ❌ 不是临床验证研究，不能据此做诊断/预警结论；
- ❌ 不是论文最终实验，公开数据上的 SFT/GRPO 数字只是**工程验证**；
- ❌ 不是 MMGraph-Agent / M³KG-RAG 的官方实现，而是独立融合复现；
- ❌ 不包含患者数据、医院编码表等授权资产（见合规边界）。

## 3. 分阶段路线

| 阶段 | 数据 | 目标 | 当前状态 |
| --- | --- | --- | --- |
| **P0 方法学框架** | 合成数据 + 公开数据（VFDB/PTB-XL/ACDC 等） | 链路跑通、接口稳定、可复现 | **进行中** |
| **P1 合作医院数据接入** | 伦理获批后的 HF/心肌病队列 | schema 映射、脱敏、标签对齐、回顾性实验 | 待伦理 |
| **P2 临床验证** | 回顾 + 前瞻队列 | AUROC、敏感度、预警提前时间、校准 | 未开始 |
| **P3 智能体部署** | 院内环境 | RAG-LLM 预警、医生在环、安全评估 | 未开始 |

## 4. 方法学框架的"完成"标准

当前阶段以**框架完整性**而非 benchmark 分数为成功标准：

- [ ] 统一的数据 schema：患者 × 时间窗 × 模态 × 标签
- [ ] 可插拔的构造 / 检索 / 记忆 / 策略 / 评测组件
- [ ] 公开数据与合作医院数据可**只改配置**切换
- [ ] 临床评测脚本：AUROC、敏感度/特异度、预警提前时间、校准
- [ ] 完整的复现文档、单测、版本记录
- [ ] 合规检查：脱敏、授权、数据不出院

## 5. 设计原则（为后期换数据而准备）

1. **数据无关接口**：`corpus.jsonl` / `qa.jsonl` schema 固定，换数据源不改代码；
2. **配置驱动**：公开数据、合作医院数据、不同模型/嵌入/检索器只改 TOML；
3. **组件可替换**：parser、extractor、embedder、searcher、policy、evaluator 均独立；
4. **实验可追溯**：每次构建记录 config、数据版本、adapter、指标；
5. **公开数据与合作医院数据严格分开报告**，不混合结论；
6. **合规优先**：患者数据只在内网/集群，编码表不入库，公开数据遵守 DUA。

## 6. 合作医院数据接入时需要改什么（预期）

| 模块 | 现在（公开/合成） | 接入合作医院数据后 |
| --- | --- | --- |
| corpus | VFDB 窗口 / PTB-XL 文档 | 患者 × 时间窗的 EMR/ECG/超声/检验文本 |
| QA | 模板生成 | 临床问题 + 医生标注/金标准 |
| 标签 | `pre/va/baseline` | VT/VF/SCD 事件 + 时间窗（如 24/48h） |
| 评测 | exact / token-F1 | AUROC、敏感度、PPV、提前时间、校准 |
| 策略 | 公开 QA 上的 GRPO | 合作医院回顾队列上的策略学习/验证 |
| 合规 | 公开 DUA | 伦理批件 + 数据使用协议 + 脱敏审查 |

## 7. 当前公开数据实验的定位

- VFDB / PTB-XL pilot：**沙盒**，用于验证"切窗→特征→语料→超图→检索→策略"链路；
- ICD-10 词表：**术语层**，为临床实体标准化做准备；
- SFT / GRPO：**算法补全**，验证训练与评测闭环；
- 所有数字（exact、F1、reward）**不得**写进临床结论或项目成果宣传。

## 8. 变更控制

任何会改变项目定位、数据边界、评测口径的改动，都应先更新本文件，再改代码。
