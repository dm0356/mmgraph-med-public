# 结构化变量抽取：意义、方法与质量标准

> 一句话：**把自由文本报告/病历变成"带单位、带时间、带出处、可计算"的变量表**。
> 它是风险模型的燃料，也是 RAG 证据层的索引。

## 1. 什么是结构化变量

以一条超声报告为例：

```text
"左室射血分数约 35%，室间隔基底段增厚约 12 mm，
 LGE 提示室间隔中层条片状强化，未见心尖部血栓。"
```

抽取结果：

| 变量 | 值 | 单位 | 时间 | 出处 | 置信度 |
| --- | --- | --- | --- | --- | --- |
| LVEF | 35 | % | 2026-01-26 | 超声报告第 2 段 | 0.98 |
| IVS_thickness | 12 | mm | 2026-01-26 | 同上 | 0.95 |
| LGE_present | true | — | 2026-01-26 | CMR 报告 | 0.90 |
| LGE_pattern | mid_wall | — | 2026-01-26 | CMR 报告 | 0.85 |
| apical_thrombus | false（明确"未见"） | — | 2026-01-26 | 同上 | 0.95 |
| SAM | 未提及（缺失，不是阴性） | — | — | — | — |

关键：**"未提及"和"阴性"必须分开**；缺失不是 0。

## 2. 为什么必须做（8 个理由）

### 2.1 模型只吃数字/类别，不吃散文

MAARS 用的不是原始报告文本，而是从报告中抽出的 **27 个心脏影像变量**（LVEF、LGE%、SAM、IVS 厚度、LA 直径、LV 容积等），加上 EHR 的 **40 个变量**。没有抽取，这 27 个变量就不存在，模型无法使用。

### 2.2 同一概念有几十种写法，必须归一

- "LVEF 65%" / "左室射血分数 65" / "EF约65%" / "LVEF：65%（Simpson）"
- "室间隔 12mm" / "IVSd 1.2cm" / "室间隔基底段增厚约12毫米"

不归一，就无法比较、无法统计、无法建模。

### 2.3 单位与量纲必须统一

- 1.2 cm → 12 mm；pg/mL vs ng/L；% vs 小数。
- 单位错误会直接毁掉模型（例如把 1.2 cm 当 1.2 mm）。

### 2.4 时间对齐（风险预测的命门）

- 变量必须带时间戳：事件前 24h/48h 的 LVEF、血钾、NT-proBNP；
- 趋势变量（LVEF 下降、HbA1c 变化、LGE 进展）需要多时间点；
- **事件后的变量不能泄漏到预测窗口**。

### 2.5 缺失与否定语义

- "未见血栓" ≠ 缺失；"可疑血栓" ≠ 确诊；
- "未查/未提及" 要标为 missing；
- MAARS 对缺失做插补，前提是**缺失是显式记录的**。

### 2.6 可复现、可审计、可统计

- 文本 RAG 的答案是概率性的，不能直接做队列统计或论文 Table 1；
- 变量表是确定的、可版本化的、可做双人核对和一致性分析（Kappa）；
- 审稿人/伦理/统计老师要能复查每个数字的来源。

### 2.7 一次抽取，多处复用

同一份变量表可以同时用于：

1. **风险模型**（Logistic/GBDT/Cox/MAARS 式融合）；
2. **知识图谱**（实体属性、超边证据）；
3. **RAG 证据**（LLM 解释"为什么高风险"时引用具体变量）；
4. **质量控制**（与报告原文比对、发现录入错误）。

### 2.8 先做基线，再上大模型

- 有了变量表，几天就能跑出 Logistic/GBDT baseline 和 AUROC；
- 没有变量表，只能直接上 LLM，成本高、不可解释、难以通过审稿。

## 3. 在系统中的位置

```text
自由文本报告（超声/ECG/CTA/CMR/病程）
        │  结构化抽取（规则 + 术语词典 + LLM + 人工复核）
        ▼
变量表（JSON/CSV，带单位、时间、出处、置信度）
        ├──► 风险模型（预测层）
        ├──► 超图/知识图谱（证据层）
        └──► RAG（解释层：引用变量 + 原文）
```

**预测层**回答"风险多高"；**证据层**回答"依据是什么"；**LLM 层**回答"为什么、下一步做什么"。

## 4. 正确做法（流程）

1. **定义变量字典**：名称、类型、单位、允许值、缺失规则、对应 MAARS/指南变量；
2. **规则 + 词典**：单位换算、同义词、否定词、区间值；
3. **LLM 抽取**：输出严格 JSON（变量名/值/单位/时间/出处/置信度），禁止自由发挥；
4. **校验**：范围检查（LVEF 0–100、IVS 3–30mm）、单位检查、时间窗检查；
5. **人工复核**：抽样双人核对，计算字段级 P/R/F1 与 Kappa；
6. **冻结版本**：变量表、抽取 prompt、模型版本一起存档；
7. **下游验证**：有无结构化变量的消融（text-only vs structured vs both）。

## 5. 质量指标

| 指标 | 说明 |
| --- | --- |
| 字段级 precision/recall/F1 | 每个变量单独算 |
| 数值误差 | 允许 ±1% 或 ±1 单位 |
| 缺失一致性 | 模型判 missing vs 人工判 missing |
| 否定/不确定识别 | "未见/可疑/考虑" 的准确率 |
| 下游增益 | 加变量后 AUROC 提升 |

## 6. 不做的后果

- 只能做"文本问答"，无法做队列统计、风险分层、论文 Table 1；
- LLM 直接读报告做预测：不可复现、不可审计、难以通过伦理/统计审查；
- 变量散落在文本里，无法发现数据质量问题（单位错误、缺失、矛盾）；
- 无法与 MAARS/指南变量对齐，无法做外部验证。

## 7. 对本项目的落地建议

1. 先定 **MAARS 对齐变量表**（40 EHR + 27 报告变量）；
2. 优先抽取高价值变量：LVEF、LGE%、IVS、LA、SAM、NSVT、AF、晕厥、家族史、血钾、NT-proBNP、eGFR；
3. 用现有 `CLINICAL_SCHEMA` 的字段承载变量，增加 `source/confidence`；
4. 在 `clinical_demo` 上先跑通抽取→变量表→Logistic baseline；
5. 等合作医院数据到位后，用真实报告做双人复核与模型验证。

## 8. 结论

> **结构化变量抽取 = 把"病历文本"翻译成"可计算的临床事实"。**
> 没有它，风险分层只是空中楼阁；有了它，预测模型、知识图谱、RAG 解释才能共用同一套可信数据。
